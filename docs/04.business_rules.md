# Business Rules

## Combination

A Combination represents:

```text
Product Type
+
Production Stage
```

The Combination ID connects the Master Plan with Lead Time Rules and Routing Hours, centralizing the workload calculation logic.

---

## Internal Start Date

Workload is allocated according to the Internal Start Date rather than the customer Need Date.

```text
Internal Start Date =
Need Date - Lead Time Days
```

Lead Time Days are defined for each Combination.

---

## Routing Hours

The Routing Matrix defines the workload generated by each Combination and Work Center.

Grain:

```text
Combination
+
Work Center
```

Measures:

- Manned Hours
- Installed Hours

For this project, every Combination generates workload across all three Work Centers.

---

## Master Plan Snapshot

Historical Master Plan versions are stored in `raw_masterplan`.

Workload calculations always use the latest available version:

```text
MAX(reference_month)
```

This ensures that future workload reflects the most recent customer forecast.

---

## Workload Calculation

Workload is generated from:

```text
Latest Master Plan
+
Lead Time Rules
+
Routing Hours
```

### Detailed Workload

Grain:

```text
Project
+
Combination
+
Work Center
```

The detailed level preserves:

- Project traceability
- Need Date
- Internal Start Date
- Required Manned Hours
- Required Installed Hours

### Monthly Workload

Detailed workload is aggregated by:

```text
Analysis Month
+
Work Center
```

This grain allows direct comparison with Monthly Capacity.

---

## Roster Snapshot

Historical workforce versions are stored in `raw_roster`.

For each analysis month, the model selects the latest Roster available up to that month:

```text
MAX(reference_month) <= analysis_month
```

Current snapshot behavior:

```text
Jan to Mar → January Roster
Apr to May → April Roster
Jun to Dec → June Roster
```

This preserves historical workforce assumptions while carrying the latest available Roster forward.

---

## Manned Capacity

Manned Capacity represents available labor hours.

It is calculated at Shift level using:

```text
Headcount
×
(Work Hours - Breaks)
×
Efficiency
×
Workdays
```

Detailed grain:

```text
Analysis Month
+
Work Center
+
Shift
```

Capacity is then aggregated monthly by Work Center.

---

## Installed Capacity

Installed Capacity represents available equipment hours.

Each Work Center currently has a fixed daily installed capacity of:

```text
72 hours per day
```

Monthly Installed Capacity is based on:

```text
Daily Installed Capacity
×
Calendar Days
```

At the detailed level, capacity is distributed across the three shifts and then aggregated back to Work Center level.

---

## Capacity vs Workload

Monthly Capacity and Monthly Workload are compared at the same grain:

```text
Analysis Month
+
Work Center
```

Two independent utilization measures are calculated in Power BI.

### Manned Utilization

```text
SUM(Required Manned Hours)
/
SUM(Manned Capacity)
```

### Installed Utilization

```text
SUM(Required Installed Hours)
/
SUM(Installed Capacity)
```

Utilization is calculated in Power BI rather than SQL so it responds correctly when multiple months or Work Centers are selected.

---

## Capacity Gap

```text
Capacity Gap =
Available Capacity - Required Workload
```

Interpretation:

```text
Positive Gap → Available Capacity
Negative Gap → Capacity Deficit
```

Manned and Installed Gaps are calculated independently.

---

## Utilization Classification

The dashboard uses the following thresholds:

```text
Below 85%   → Healthy
85% to 100% → Attention
Above 100%  → Overload
```

These rules are applied consistently to KPI cards and Work Center heatmaps.

---

## Planning Scope

The solution uses:

- 12-month planning horizon
- Monthly analysis
- Work Center-level capacity comparison
- Project-level workload traceability
- Shift-level capacity detail

The solution supports tactical and strategic planning and is not intended for daily production scheduling.
